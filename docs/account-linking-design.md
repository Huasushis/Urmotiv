# 账号与第三方登录调整方案

本文记录生产试用后确认的设计；实现与部署完成前不代表功能已上线。

已实现自由用户名、密码与邮箱管理、USTC 主动绑定/解绑及独立认证资料展示。这些操作保持站内账号 ID 不变；正式站点的统一身份提供方仍保持关闭，启用需要管理员配置可用的客户端和回调地址。

## 一个账号，多种登录方式

题目、审核、权限、比赛始终关联站内账号 ID。用户名、联系邮箱和第三方身份都不是业务记录的主键。
注册可自由选择唯一用户名；推荐使用学号时将字母大写，但不强制学号格式。用户名不区分大小写。

USTC 身份用提供方和 `gid`（接口中的 `id`）共同唯一识别。学号与姓名只是认证属性，不能用于自动合并账号。
现有账号在「个人资料 → 关联登录」输入当前密码后主动绑定。签名状态绑定发起浏览器、当前会话摘要、账号和认证版本，一次性消费；途中换账号、换会话或凭据版本变化都会拒绝绑定。
未绑定身份按管理员“首次登录自动建号”设置处理：启用且用户名/邮箱没有冲突时创建独立账号；关闭或冲突时返回登录页，提示先登录已有账号再主动绑定，也可先注册。任何情况都不按相同学号、姓名或邮箱自动合并账号。

## 个人资料与学校认证信息

联系资料包括昵称、邮箱、QQ 和头像，由本人维护。学校返回的学号、姓名、邮箱单独注明来源，作为只读的认证信息展示。
第三方登录只补齐空姓名；已有用户名、姓名、联系邮箱不会被后来登录静默覆盖。空联系邮箱只在提供方明确声明已验证时补齐；其余邮箱留在学校资料中供参考。首次自动建号可预填学校邮箱，但未声明验证时仍须本人在个人资料发送验证邮件。关闭公开注册不会阻止已有账号验证自己的邮箱。
OAuth 客户端配置由管理员管理，不从个人资料界面读取或回显密钥。第三方登录开关和个人绑定记录相互独立，临时关闭提供方不会删除绑定。

## 修改与恢复

- 修改密码要求当前口令或近期独立身份验证，成功后撤销旧会话及密码恢复链接。
- 忘记密码向已验证邮箱发送短期、一次性链接；请求响应不暴露账号是否存在。
- 更换邮箱先验证新邮箱，成功后再替换联系邮箱，通知旧邮箱；链接一次性使用，冲突或过期不改变旧邮箱。
- 主动解绑需要重新验证当前身份，且解绑后至少保留一种可用登录方式。单纯存在但尚未验证的邮箱不算可用方式。
- 只通过学校身份登录且尚无密码的账号，在最近 10 分钟内直接认证、并且没有未验证联系邮箱时，可设置初始本地密码；初始设置不能覆盖已有密码。否则先验证邮箱并通过邮件找回，或重新认证。
- 模拟登录会话不可更改目标用户的密码、邮箱或第三方绑定。
- 认证变更写入不包含口令、令牌、学校票据或个人属性正文的审计记录。

## 验收

覆盖正常绑定/解绑、跨浏览器与跨账号回调、重复或过期状态、一个身份绑定两个账号、提供方关闭、邮箱冲突、旧会话撤销及最后登录方式保护。
新流程须继续支持现有本地账号，USTC 提供方在完成独立验证前保持关闭。
