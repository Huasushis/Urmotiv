## 本阶段新增/改动的主要内容

### 文件链路（apps/api）

- `problem-file-service.ts`：题目文件服务。列举按 `canReadTestdata` 收窄类别；上传先发布
  对象文件、再在同一事务里创建修订+复制旧关联+写元数据+建关联，失败删除刚发布对象；
  下载由 API 转发流式内容（每次请求全量权限检查，无长期地址）；删除只在新修订取消关联。
- 路由：`GET/PUT /api/v1/problems/:id/files`、`GET/DELETE /api/v1/problems/:id/files/:fileId`。
  上传用 `application/octet-stream` 正文 + 查询参数（`uploadProblemFileQuerySchema`）。
- `database-store.ts`：新增 `createProblemWithRevisionAction`（与 replace 版对称，创建题目
  首个修订后、事务提交前执行回调）。

### ZIP 与题目包（packages/problem-package）

- `zip.ts`：纯 node:zlib 的 ZIP 读写。自解析 central directory，在解压前拒绝符号链接、
  设备文件、加密、分卷、zip64、未知压缩法与危险路径；`inflateRawSync` 的 `maxOutputLength`
  按目录声称大小限制解压，实际大小与 CRC 再校验；`writeZipArchive` 输出确定性字节。
- `archive.ts` 的问题代码新增 `not_a_zip_archive`、`unsupported_archive_feature`。

### 后台任务运行时（packages/jobs ← apps/worker）

- `worker-types.ts`、`worker-runtime.ts`（JobWorker）、`problem-package-handlers.ts` 从
  apps/worker 移入 packages/jobs；apps/worker 对应文件保留为同名转发,对外导入路径不变。
  jobs 因此新增依赖 problem-package 与 plugin-hydro-format。

### 题目包生产依赖与传输接口（apps/api）

- `problem-package-runtime.ts`：四个生产实现。
  - StorageVerifiedImportArchiveReader：按元数据+摘要读取上传包并做全部 ZIP 安全检查；
  - DatabaseImportedProblemWriter：canonical → 题目。对象文件先发布，题目/修订/样例/标签
    /文件元数据/关联在一个事务（createProblemWithRevisionAction），失败清理对象文件；
    以 (jobId, position) 幂等；未知标签丢弃；`format_extensions` 原样保存；
  - ServiceExportReadAuthorization：worker 每次读题/读文件前重查 canExport 与内部类别的
    testdata.read；
  - DatabaseFixedRevisionExportReader / StorageExportArtifactWriter：按固定修订读内容与
    文件；产物打 ZIP（多题外层 ZIP）写入对象存储（purpose=export_output，默认 72 小时）。
- `transfer-service.ts` + 路由 `/api/v1/transfer/...`：
  - `POST /uploads`（需 `problem.import`；先安全检查后登记，purpose=import_input,24 小时过期；
    返回各格式识别建议）；
  - `POST /imports/preview`、`POST /imports`（幂等）、`GET /imports/:jobId`（仅本人，他人 404）；
  - `POST /exports/preview`（逐题给出 ready/blocked/not_found 与丢失信息；无权与不存在
    完全一致）、`POST /exports`（服务端重算 lossSummary，固定修订）、`GET /exports/:jobId`、
    `GET /exports/:jobId/download`（任务归属+逐题权限+过期三重检查后流式转发）。
  - 导入 choices 目前固定 `create`；更新已有题目留待后续版本。
- `server.ts`：组装以上全部 + 进程内 LocalJobQueue + 内嵌 JobWorker（`api-embedded-*`）。
  第一阶段题目包任务在 API 进程内处理，不经过 Redis；接口已抽象，之后拆独立 worker 时
  只需把 runtime 实现移到共享包并切换队列。

## 关键安全边界（不变，实现已遵守）

- `packages/storage` 只管字节；权限永远在 API 服务层判断。
- `storageKey`、对象存储路径、内部附件名不进入任何响应、任务报告或日志；任务失败文案
  一律来自固定映射（`safeProblemPackageFailure`）。
- 无权访问题目、文件、任务、导出包统一按“不存在”返回。
- 明确拒绝优先；机器人固定禁止项在账号类型阶段拦截。
- 不实现代码评测执行器。
