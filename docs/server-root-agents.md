# `/home/ubuntu/codex-urmotiv` 顶层开发约定

本文件会复制成服务器 `/home/ubuntu/codex-urmotiv/AGENTS.md`，适用于这个目录下的三个独立仓库。新会话从这个目录启动后，先完整阅读同目录的 `README.md` 和 `HANDOFF.md`，再按下面顺序阅读各仓库自己的说明。

## 开始顺序

1. 完整阅读根目录 `README.md`、`HANDOFF.md` 和 `PROMPT-FOR-NEXT-AI.md`，理解正式仓库与旧实验资料的区别。
2. 运行只读命令，确认三个正式仓库的分支、提交和未提交文件；不要先安装、格式化或改代码。
3. 阅读 `Urmotiv/AGENTS.md`、`Urmotiv/docs/spec.md`、`Urmotiv/docs/permissions.md`、`Urmotiv/docs/problem-package.md`、`Urmotiv/docs/plugins.md`。
4. 阅读 `Fermata/AGENTS.md`、`Fermata/README.md`，特别是“当前校准状态”。
5. 阅读 `Anklang/AGENTS.md`、`Anklang/README.md`、`Anklang/docs/plan.md`。
6. 在不输出内容的前提下确认 `Urmotiv/private/urmotiv.txt` 存在，然后在服务器本地阅读。它是用户最初的产品想法；最终验收必须逐项对照它，不能只依赖公开规格的摘要。

## 目录与隔离边界

- `Urmotiv/`：题库、投题、审题、组题、导入导出、权限和插件宿主。
- `Fermata/`：独立的 AI 审题服务，只通过带版本号的 HTTP 接口与 Urmotiv 通信，不共享数据库。
- `Anklang/`：独立的原题检索服务，也不共享数据库。
- `previous-server-work/`：迁移前的服务器实验环境、实验结果、私有配置和研究资料，按原目录完整保存。它不是正式代码来源，不能批量删除；需要复现实验或核对旧结果时按 `README.md` 定位。
- `validation/`：目录迁移和后续部署验证的记录，只放不含题面、密钥和模型原始回答的安全摘要。
- `.tools/`、`.cache/`：如需自行安装 Node.js、pnpm 或其他工具，优先放在这里。

用户允许在服务器安装软件和调整配置，但授权范围不是整个用户目录。服务器上还有其他项目：只在 `/home/ubuntu/codex-urmotiv/` 及其明确属于本项目的进程中操作，不整理用户主目录，不修改其他项目，不使用宽泛路径执行删除、移动、改权限或搜索替换。主目录下的其他文件和目录一律视为不属于本项目，不能凭名称猜测归属；`/home/ubuntu/cc.sql` 明确不属于本项目，不得查找、恢复或处理。

结束进程前必须同时核对进程号、父进程、完整命令和当前工作目录。只结束能确认属于 `/home/ubuntu/codex-urmotiv/` 的进程；不得按进程名批量结束 `node`、`python`、`pnpm` 等进程。

## 服务器网络与工具

- `127.0.0.1:10808` 同时提供 HTTP 代理和 SOCKS5 代理，代理变量已经写入用户的 `.bashrc`，可访问外网。
- 新终端先用 `env` 检查代理变量是否实际进入当前进程。非交互命令不一定读取 `.bashrc`；需要时只在当前命令或当前会话中明确设置代理变量，不改动其他项目的配置。
- 可以安装缺少的软件，但先检查现有版本和磁盘空间。优先把项目专用工具和缓存放进本目录，避免改变其他项目依赖的系统版本。
- 这次从 Windows 完整复制了仓库，依赖目录中的链接可能在复制时被展开，里面也可能有 Windows 平台产物。不要把复制来的 `node_modules` 当成 Linux 已安装依赖；在确认锁文件后用服务器上的包管理器重新核对或安装。

## Git 与文件安全

- 三个仓库都有自己的 `.git`。先分别运行 `git status --short --branch`、`git log -5 --oneline --decorate`。
- Urmotiv 当前有多组未提交工作，而且可能互相无关。不得 `git reset`、`git checkout --`、`git clean`，也不得把全部改动一次性提交。先按 `HANDOFF.md` 的分组逐个审阅、测试、提交。
- 删除源文件也要谨慎；无法确认归属时保留文件并写清楚用途。不要覆盖另一个智能体留下但尚未提交的内容。
- 用户允许推送。完成一组有明确边界、通过相应测试的修改后，及时创建小提交并推送当前 `codex/` 分支。提交前再次检查暂存清单，避免带入私有资料、报告原始响应或无关修改。

## 私有资料与密钥

- `Urmotiv/private/`、`Urmotiv/hist_problem/`、`Urmotiv/USTC题目列表.xlsx` 及 Fermata 的私有标定材料只能留在服务器非 Git 区域。旧服务器的私有实验资料仍在 `previous-server-work/urmotiv-codex/private/` 和相关 Fermata 实验目录中；读取前先看根目录 `README.md`，不得把它们复制进正式仓库的跟踪文件。
- 不得把真实题面、题解、测试数据、附件、题目表格、模型原始响应、账号、密码、令牌或密钥写入 Git、日志、错误信息、任务报告或聊天回复。
- 只输出安全的文件数量、大小、哈希或是否存在；不要用会把文件内容带进终端记录的命令检查私有资料。
- 不要用 shell 的 `source` 或 `.` 加载 `.env`。值中的特殊字符可能让命令失败并把密钥显示出来。Fermata 必须使用 `scripts/run-with-env.mjs <环境文件> <命令>`。
- 在把历史 USTC 私有题面或题解发送给外部模型前，必须先向用户逐字确认：

  > 是否明确同意把历史 USTC 私有题目的题面和题解发送给当前配置的外部模型服务，用于准确性标定？

  尚未得到这项明确同意时，只能使用公开题目或人工脱敏材料。

## 不可违反的产品与安全规则

- 权限必须在服务端检查。隐藏按钮只改善界面，不是权限控制。
- 无权读取私有题目、文件、后台任务或导出包时统一按“不存在”返回；标题、文件名、存储位置、筛选总数和错误差异都不能泄露题目存在。
- 明确拒绝永远优先于角色或插件允许。机器人账号固定禁止删除题目、删除用户、模拟登录、管理权限、管理系统和读取密钥，任何插件都不能解除。
- 题目包导入必须防止压缩包内路径跳出目标目录、符号链接、压缩炸弹、重名覆盖和超限文件。导出任务在创建和下载时都重新检查权限。
- 修改权限、认证、附件访问、导入导出或插件调用时，必须补无权访问与失败路径测试。
- Urmotiv 是命题协作系统，不执行选手代码。题面与题解使用 Markdown；Markdown 是用普通文本标记标题、公式和代码的写法，便于版本管理和安全预览。
- 用户界面和文档默认简体中文。不得为了显得专业而造新词；必须使用技术名词时，第一次出现就用日常语言解释它是什么、为什么需要它。

## 测试与外部模型调用

- 所有构建、测试、迁移、服务启动和浏览器联调都在服务器运行。涉及页面时用 Playwright 检查桌面和手机；Playwright 是自动控制浏览器的测试工具，用来发现按钮不可点、文字溢出和窄屏布局问题。
- 先测试受影响工作区，再跑完整基线。不要因为复制完成就声称当前未提交代码已通过测试；`HANDOFF.md` 明确记录了哪些修改仍未验证。
- Fermata 的“接口测试通过”和“判断准确”是两件事。测试通过只能证明程序按约定运行；准确性必须用足够大、有人工作为答案的标定集衡量，并保留修改前后两份报告。
- 不得恢复 120 秒总时限。对正常持续输出的付费模型请求应使用流式接收并等待服务端结束；流式接收是边生成边读取返回内容，可以区分迟迟没有首段输出、输出中途停住、正常慢速生成和主动取消。短时限会产生 499“客户端已取消”，浪费已经发起的付费请求。
- 调整提示词、处理步骤、难度映射或阈值之前，先运行完整基线实验；任何缺失、499、取消或跳过样本都必须让报告判为不完整，不能拿不完整结果宣布提升。

## 完成一项工作的最低要求

1. 静态审阅当前差异和权限边界。
2. 在服务器运行受影响工作区的类型检查、单元测试和构建；页面改动再跑桌面与手机浏览器测试。
3. 对权限、导入导出、附件或插件改动补无权访问和失败路径测试。
4. 检查暂存文件中没有私有资料和无关改动。
5. 小步提交并推送，在交接文档中记录真实命令、结果和未解决事项；不得把“未运行”写成“通过”。
