# 权限设计

这份文档说明“谁能对什么做什么”。实现和测试必须以本表为准，不能只根据页面上是否显示按钮判断。

## 1. 计算顺序

每次请求按以下顺序判断，前一步不通过就立即停止：

1. **账号状态**：账号存在、未被禁用、会话或令牌仍有效，并且有登录权限。
2. **账号类型限制**：机器人和临时服务账号先应用不能解除的固定禁止项。
3. **对象范围**：确认题目所有者、指定授权、比赛成员和当前审核分配。
4. **明确拒绝**：收集用户、角色和对象授权中的拒绝；只要有一项拒绝，结果就是拒绝。
5. **允许**：至少有一项与动作和范围匹配的允许才可继续。
6. **状态规则**：例如待审状态的基础题面和基础题解两个冻结字段，即使有编辑权限也不能修改；题目名称可继续编辑；只有专门的强制修改权限可处理冻结字段，且必须审计。

插件可以在第六步之后增加限制或要求额外检查，但不能把前五步的拒绝改成允许。

后台任务和其他跨请求写入在最终数据库事务中复查权限时，以目标账号的 `users` 行作为
并发串行点：先锁用户行，再按稳定顺序锁角色成员关系和已有授权，最后重新读取权限。
运行时新增、撤销或修改账号状态、角色成员关系、用户授权、角色授权时，也必须先锁受影响
账号的用户行。只锁已有授权行不能阻止另一事务插入一条新的明确拒绝，因此不能省略用户行；
绕过服务直接写 SQL 不属于受支持的权限管理路径。

## 2. 权限名称

权限名采用 `对象.动作.范围`，只是程序中的稳定名称。界面必须显示中文解释。

### 2.1 账号和系统

| 权限 | 含义 | 默认角色 |
| --- | --- | --- |
| `auth.login` | 登录并使用系统 | 除已禁用账号外 |
| `user.create` | 单个或批量创建账号 | 组长、系统管理员 |
| `user.delete` | 删除或停用普通账号 | 系统管理员 |
| `user.impersonate` | 以其他用户身份排查问题 | root（仅专用本地登录）；真人账号默认不授予 |
| `user.permission.manage` | 修改角色和权限 | root、受信任系统管理员 |
| `system.manage` | 修改站点、认证、存储等重要配置 | root、受信任系统管理员 |
| `plugin.manage` | 管理已内置插件的启停和配置 | root、受信任系统管理员 |
| `service_account.manage` | 创建机器人账号和令牌 | root、受信任系统管理员 |
| `tag.manage` | 以真人账号新增、重命名、移动、排序、停用、恢复和删除知识点目录，并处理对当前题目的影响 | 组长、指定管理员 |
| `audit.read` | 查看审计记录 | root、指定管理员 |
| `review.policy.manage` | 修改审核轮次使用的审核策略，不包含单题最终确认 | 组长、受信任系统管理员 |
`user.permission.manage`、`system.manage` 和 `plugin.manage` 都是高风险权限，账号不能通过修改自己的角色或用户增量直接提升这些权限。
除 root 等价权限、自我提升和机器人固定禁止项外，不按“操作员”或“系统管理员”角色名称设置通用授权上限；管理人可以按实际授权管理其他账号和角色的核心权限，但任何明确拒绝仍然获胜。

| 权限 | 含义 |
| --- | --- |
| `problem.create` | 新建题目 |
| `problem.view.own` | 查看自己创建的题目 |
| `problem.edit.own` | 编辑自己题目中当前允许编辑的字段 |
| `problem.delete.own` | 删除自己的草稿；已提交题目不能直接删除 |
| `problem.view.all` | 查看全部题目；仍受单题明确拒绝影响 |
| `problem.edit.all` | 编辑全部题目中当前允许编辑的字段 |
| `problem.delete.all` | 删除题目；使用软删除并记录审计 |
| `problem.review` | 对有查看权限的待审题目提交意见 |
| `problem.status.change` | 最终确认通过、不通过或强制撤回 |
| `problem.frozen.edit` | 修改冻结字段；仅紧急修正，必须填写原因 |
| `problem.access.grant` | 给指定用户授予或拒绝单题权限 |
| `problem.viewers.read` | 查看谁看过题面及活动时长 |
| `problem.import` | 导入题目包 |
| `problem.export.own` | 导出自己的完整题目包 |
| `problem.export.all` | 导出有权查看的任意题目完整包 |
| `problem.testdata.read` | 下载测试数据、标准程序和内部附件 |
| `problem.testdata.write` | 上传和配置测试数据、程序和内部附件 |

`problem.view.all` 不自动包含测试数据和标准程序读取权；题面可见和内部评测资料可见必须分开。

### 2.3 组题与比赛

| 权限 | 含义 |
| --- | --- |
| `contest.create` | 新建组题方案或比赛 |
| `contest.edit.own` | 编辑自己创建的组题方案 |
| `contest.edit.all` | 编辑任意组题方案 |
| `contest.delete` | 删除组题方案 |
| `contest.export` | 导出比赛和其中题目 |
| `contest.risk.read` | 查看题目访问者与参赛者的泄题风险交集 |

普通投稿人默认不拥有上述任何权限。

## 3. 范围和单题授权

一个权限记录包含：

- 结果：允许或拒绝；
- 权限名；
- 范围：全局、自己的对象或指定对象；
- 可选到期时间；
- 授权人和原因。

指定题目授权只作用于该题目，不能隐含获得列表中其他题目的标题。列表查询把全局范围、所有权和指定题目授权合并为数据库条件。

对于同一动作，拒绝不比较“更具体”还是“更高级”：任何匹配的拒绝都获胜。这样容易解释，也符合“禁止优先级最高”。

### 3.1 角色基线与用户增量

角色权限是账号的基线；用户还可以拥有独立的允许/拒绝增量（per-user delta）。增量同样受作用域和到期时间约束，不会修改角色定义，也不能把 root 账号改成普通用户增量。

对当前账号、动作和对象，先合并所有有效角色与用户增量中的允许项，再扣除所有有效的拒绝项：
`effective = (角色 allow ∪ 用户 allow) - (角色 deny ∪ 用户 deny)`。只有匹配作用域且未过期的记录参与计算；任意匹配的明确拒绝都优先于允许。机器人固定禁止项在这一步之前直接生效，插件不能解除。

## 4. 默认角色包

角色包只是初始建议，可由有权限的人调整。调整后仍受固定限制和明确拒绝影响。

### 投稿人

- `auth.login`
- `problem.create`
- `problem.view.own`
- `problem.edit.own`
- `problem.delete.own`

默认不允许导入、导出、查看他人题目、内部测试数据、比赛和访问者记录。

### 审题人

包含投稿人权限，并增加：

- `problem.view.all`
- `problem.review`
- `problem.testdata.read`（可按实际分组移除）

不自动拥有 `problem.edit.all`、`problem.status.change` 或删除权限。

### 命题组成员

包含审题人权限，并增加：

- `problem.edit.all`
- `problem.testdata.write`
- `problem.viewers.read`
- `contest.create`
- `contest.edit.own`
- `contest.risk.read`

### 组长

包含命题组成员权限，并增加：

- `problem.status.change`
- `problem.access.grant`
- `problem.import`
- `problem.export.all`
- `contest.edit.all`
- `contest.delete`
- `contest.export`
- `tag.manage`
- `user.create`

是否增加系统配置与插件管理应单独决定，不能因为是组长自动获得服务器密钥。

### 系统管理员

- 账号、权限、系统、插件、机器人、审计、审核策略和标签管理权限；
- 额外拥有 `problem.view.all` 与 `problem.import`，因此可以进入题库和导入历史；
- 不默认拥有 `problem.status.change` 或 `problem.review`，不自动拥有最终审题决定权；
- 不因管理权限自动读取题目附件、测试数据或客户端密钥。

### root

编号固定为 `0` 的 `root` 只作为数据库初始化和紧急恢复身份。它的内部角色保留当前核心权限的完整全集；新增核心权限也必须同步纳入 root 基线。root 不是 OAuth、CAS 或邮箱身份，不用于日常登录，且不能成为模拟登录目标。
bootstrap 完成后 root 不会自动获得本地凭据；需要恢复时只能由真实服务器 TTY 执行 `recover-root-credentials`，由服务端设置一次本地口令并撤销其旧会话。root 的本地登录只使用专用入口，不能通过网页 demo、邮箱、CAS 或 OAuth 旁路取得权限。
真人系统管理员必须使用独立账号；不能为 root 增加第二套身份、绕过 TTY 恢复或留下隐藏的网页后门。

## 5. 机器人固定禁止项

以下动作在账号类型检查阶段直接拒绝，角色、用户覆盖、单题授权和插件都不能解除：

- `user.delete`
- `user.impersonate`
- `user.permission.manage`
- `system.manage`
- `plugin.manage`
- `service_account.manage`
- `tag.manage`
- `problem.delete.own`
- `problem.delete.all`
- `contest.delete`
- `audit.read`

机器人可以在被授予后查看待审题目、提交审核、写入评分和创建后台结果，但不能把自己的意见直接变成最终状态，
除非核心配置明确允许某个经过校验的审核规则使用机器人意见。即便如此，状态改变由核心服务执行，不由机器人接口直接执行。

机器人令牌的权限是账号权限的上限，不是另一份额外授权。令牌只能保存不重复的核心权限、全局允许项，必须包含
`auth.login`，也不能包含上述固定禁止项；数据库中已有令牌若不符合这些条件，认证直接失败。一次请求只有在账号策略和
令牌权限都允许时才能继续，账号上的明确拒绝仍完整保留。令牌限定了来源地址时，服务端只使用连接地址，或在连接来自
明确配置的可信代理时从右向左核对 `X-Forwarded-For`；无法可靠解析来源地址就拒绝认证。账号、令牌、来源地址和双方的
`auth.login` 全部验证成功后才更新令牌最近使用时间。

机器人领取任务时固定记录当时的题目修订和审核轮次提交修订。领取、续租和完成都在数据库事务中依次锁定题目、
当前审核轮次和领取记录，再重新读取账号、令牌及权限；题目不可见、`problem.review` 被拒绝、轮次已关闭、提交修订
不一致或题目修订已变化时，不能写入意见。轮次关闭会在同一事务中结束仍有效的机器人领取记录。

续租和完成请求必须带由调用方生成、并在同一次操作重试中复用的 UUID 请求标识。服务端保存不含正文的载荷
摘要和固定结果；同一领取记录用相同请求标识和相同载荷重试时只重放原结果，不重复续租、写意见或写审计，用相同标识
提交不同载荷则返回冲突。这使客户端在响应丢失后可以安全重试，而不必猜测服务端是否已经提交。缺少请求标识的旧客户端
请求固定按无效输入拒绝；部署前必须先升级 Fermata，使它为每次操作生成并稳定复用 UUID。

## 6. 关键接口的额外规则

### 读取题目

- 无题面查看权：返回 `404`，响应不包含标题、作者或状态。
- 有题面查看权但无测试数据权：题目响应不查询测试文件表，也不返回文件数量和文件名。
- 有题面查看权：可以查看当前审核轮次的公开评价字段；没有审题权限也不影响读取这些公开字段。
- 审核私密备注只返回给评价提交者本人、当前有效审题人和有最终决定权的人；题目作者不会仅因是作者就看到这些备注，具体来源还可增加更严限制。

### 修改审核意见

- 每名审题人每轮只能创建或修改自己的一份意见，接口不接受目标审题人或其他意见编号。
- 保存意见后，服务端重新执行本轮审核规则；结论变化可能立即使题目通过或不通过。
- 已通过、已拒绝或已撤回的审核轮次只读，不能继续修改其中的意见。
- 原创性是公开的独立结构化字段。新增或更新意见时取 1 至 5；迁移前历史意见可以为 `null`，不能根据题目质量或默认值补造。

### 写回审核建议

- 无题面查看权时返回与题目不存在相同的 `404`，不能泄露建议、知识点、轮次、当前值或是否可以写回。
- 有题面查看权的人可以查看由公开评价字段得到的只读建议；私密备注不参与建议，也不能由建议接口返回。
- 写回者必须是人类账号，并且对该题同时拥有 `problem.status.change` 和当前有效的题目编辑权限。任何匹配的明确拒绝仍然优先；
  作者仅凭所有权、普通审题人和机器人都不能确认写回。
- 只允许写回当前已经通过并关闭的审核轮次，且题目此刻仍为审核通过。轮次、修订或状态已经变化时返回 `409`，不能回退到
  旧的通过轮次继续写入。
- 专用请求只接受 `expectedRound`、`expectedRevision` 和需要应用的字段名，不接受建议数值、知识点值、状态或审核意见编号。
  字段列表为空、重复或包含未知字段时返回 `422`。
- 服务端必须在锁定题目的同一事务中，按关闭轮次冻结的 `countedOpinionIds` 重新计算所选建议，校验全部意见编号和知识点，
  再创建题目修订。冻结列表为空时不生成建议；不能使用浏览器计算结果，不能用 `usedOpinionIds` 替代，也不能在部分编号或
  知识点失效时只写可用部分。
- 看得到题目但缺少上述确认权限时返回 `403`。题目修订、文件关联和不可修改的审计记录必须一起成功；任一步失败都整体回滚。
  审计只保存轮次、修改前后修订号、字段名和意见数量，不保存题面、题解、评价正文、私密备注、知识点列表或聚合具体值。

### 修改题目

- API 接受字段白名单，先比较变更前后值，再按状态拒绝冻结字段。
- 不接受浏览器提交的 `ownerId`、审核聚合结果或状态作为普通字段更新。
- 强制修改冻结字段使用单独接口、单独权限和必填原因。

### 管理知识点目录

- 登录用户可以读取当前启用的分类和标签，用于题目编辑、筛选和查看；只有同时为真人账号且拥有 `tag.manage` 的用户可以调用
  管理接口。机器人、权限明确拒绝和缺少权限均返回 `403`，页面是否显示管理入口不参与授权。
- `tag.manage` 授权的是全局目录操作及其必要的题目当前修订更新，不自动授予题面、题解、附件、历史意见或比赛内容查看权。
  删除影响预览只返回当前题目数、唯一标签题目数、历史修订引用数、审核意见引用数和子标签数等汇总，不返回题目编号、标题、
  作者或链接，也不能据此进入题目详情。
- 新增、重命名、移动、排序、停用、恢复、删除和别名修改都必须携带预期目录版本。服务端在事务内重新检查账号、固定禁止、
  明确拒绝和版本；版本或影响已经变化时返回 `409`，不能部分执行或覆盖并发修改。
- 停用或删除被当前题目使用的标签时，服务端为每道受影响题目创建新修订并从当前标签集合中移除它。题目仍有其他标签时保留
  其余标签；它是唯一标签时必须提供当前启用的替代标签，否则整个事务失败。该专门操作不要求管理员另有这些题目的编辑权，
  也绝不授予其读取内容的能力。
- 历史修订、旧审核意见和比赛固定快照中的引用不得删除或改写，只显示为“已停用”。分类有子标签时不能删除，不能隐式级联；
  普通在线接口不物理删除有任何历史引用的稳定编号。
- 题目新修订、目录停用、目录版本递增和不可修改的审计必须一起成功。审计只保存稳定编号、前后目录版本、汇总影响数量和
  是否使用替代标签，不保存受影响题目编号、标题、内容、审核正文或知识点名称列表。完整行为见
  [知识点目录与管理规格](tag-taxonomy.md)。

### 附件与图片

- 文件编号不等于公开地址。下载时从文件查到所属题目和文件类别，再计算权限。
- 题面内图片也使用受控下载地址；导出时由后台任务复制到包内相对路径。
- 下载地址短期有效且绑定用户或一次性任务，权限撤销后不能继续使用旧地址。

### 导入导出

- 导入接口需要 `problem.import`，不能通过创建题目接口偷偷上传完整包。
- 导出任务创建时记录允许导出的题目版本和文件类别；真正读取每个文件及下载时再次检查。
- 比赛导出额外需要 `contest.export`，拥有单题导出不等于能看到比赛题目集合。

### 模拟登录
当前仅允许固定 `root` 账号作为真实操作者发起模拟登录；真人系统管理员默认没有 `user.impersonate`，机器人永远不能发起。root 也不能把自己或另一个 root 身份作为模拟目标。
模拟会话只改变当前请求的 effective 用户，不改变 actor 的身份、权限来源或 root 约束；不能修改被模拟用户的密码、邮箱、权限或令牌，也不能再模拟第三个用户。
服务端权限检查保留真实 actor，并按 effective 用户执行目标对象规则；审计同时保存 actor 和 effective 身份，不能只记录被模拟用户。

## 7. 必须通过的越权测试

1. 投稿人用连续、随机和已知题号请求他人题面，全部只得到 `404`。
2. 投稿人请求他人题面图片、附件、测试数据、导出任务和任务下载地址，均失败且不泄露文件名。
3. 投稿人不能通过筛选、排序、总数、自动补全或错误信息推断私有题目。
4. 用户从一个角色获得允许、另一个角色获得明确拒绝时，拒绝获胜。
5. 禁止登录后，已有网页会话、API 令牌和下载地址立即失效。
6. 机器人获得管理员角色后仍不能调用固定禁止接口。
7. 待审与通过题目只能修改非冻结字段（基础题面和基础题解冻结，题目名称可编辑）；批量接口、导入接口和插件同样不能绕过。
8. 导出任务创建后撤销权限，任务结果不能下载。
9. 删除或停用审题人后，其旧审核不会被新一轮自动规则错误计入。
10. 插件抛错、超时或返回畸形结果时，核心权限检查和状态事务不会被跳过。
11. 机器人即使获得组长或系统管理员角色也不能调用 `tag.manage`；真人缺少权限或有明确拒绝时同样失败。
12. 标签删除预览不返回私有题目标识或内容；目录版本或题目当前修订并发变化后，旧确认请求返回 `409` 且不做部分更新。
13. 删除题目当前唯一标签而未提供启用的替代标签时，题目修订、标签状态、目录版本和审计全部保持不变。
14. 停用标签只改变当前题目新修订；历史修订、旧审核意见和比赛固定快照不被改写，恢复标签也不会把它自动加回题目。
