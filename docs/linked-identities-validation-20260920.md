# 关联身份验收

以 provider + gid/id 关联已有账号，用户名、联系邮箱和学校属性分别保存；提供方在正式站点仍关闭，不宣称已完成真实学校接入配置。

- OAuth 库 2 文件 12 项通过：签名上下文、防篡改、浏览器 Cookie、一次性状态及原有传输边界。
- API 4 文件 35 项通过：USTC 回调、关联数据库事务、账号安全和经典 CAS 浏览器绑定。另有个人资料/OAuth 集成、密码数据库及会话持久化回归通过。
- 覆盖自由用户名主动绑定、后续学校属性更新不覆盖本地资料、跨账号/跨会话回调拒绝、同一身份并发抢绑只有一个成功、提供方停用保留记录、最后登录方式保护、解绑指定身份且保留同提供方其他旧关联、旧会话和旧关联登录失效。
- 没有邮箱和本地密码的学校账号可在近期直接认证后设置初始密码。不能覆盖已有密码；过期直接会话、模拟会话与 root 不允许初始化。新学校邮箱默认未验证，个人验证不依赖公开注册开启。
- 桌面/手机均跑通注册本地账号 → 登录 → 学校身份绑定 → 认证资料独立显示 → 解绑 → 原用户名密码再次登录，用户名和联系邮箱始终保持。既有密码/换邮箱/找回完整浏览器流程同时通过，共 4 项。
- 浏览器使用实际 Fastify HTTP 服务和合成学校授权页面，未向真实学校发送登录请求。初次测试的模拟 HTTP 重定向链绕过 Playwright 后续拦截、落入默认演示 API；改为合成确认页发起独立回调导航后，Cookie 与签名校验完整通过，未放宽生产校验。
- Web 全量 154 项通过；个人资料、关联面板的桌面/手机截图已检查，窄屏无横向溢出。

本批复用 existing identities 的资料列及 sessions 的创建时间，无新增数据库迁移。生产发布检查应确认入口、匿名边界、提供方仍关闭及已关联记录保留，不能用合成学校测试宣称真实提供方已启用。
