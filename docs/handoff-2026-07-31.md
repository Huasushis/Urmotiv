## 三、Urmotiv 题目包

当前实现仍在内存中处理 ZIP，所以原始包、单个文件和解压后全部文件默认都不得超过
128 MiB。普通题目附件上传仍使用原来的 512 MiB 路由限制，没有被题目包限制连带缩小。

多题导出会先检查所有题目与文件权限，再检查已保存文件的总大小；无权用户不能从“容量超限”
推断私题是否存在。生成目标格式后还会逐题累计实际字节，达到上限立即停止，不再生成后续单题包，
也不会把半成品写入对象存储。

最终复审额外修复了两个问题：

1. 旧实现会先把所有单题 ZIP 放进内存，最后才检查多题外层包；现在改为逐个生成、逐个累计。
2. 带启动程序前缀并在末尾再附加数据的 ZIP 可能绕过嵌套包识别；现在也会保守拒绝。

服务器验收：

- `problem-package`、`jobs`、`api`、`worker` 四个工作区类型检查和构建通过；
- 定向测试分别为 35、4、13、12 项，全部通过；
- API 全套 165 项通过；最后两个修复又单独通过 API 类型检查、构建和题目包接口定向测试。

## 四、Anklang

Anklang 仍只使用 Python 标准库，公开仓库没有真实抓取源或真实题目。生产默认使用反向代理，
本地检索引擎和示例来源保留。

本轮保证以下行为：

- 外部检索、模型复核或文字转数字服务失败时，返回固定且不泄露内容的结果；
- 失败或只完成一部分的结果不写缓存，下一次请求会真正重试；
- 默认只提示相似题，不因相似度分数自动拦截投题；
- 旧数据库并发首次打开时只迁移一次，损坏向量不会拖垮整次查询；
- 没有可靠更新时间的批次不推进来源游标，旧格式游标可以安全替换；
- 一个来源读取或解析失败不影响后续来源，命令行不打印原异常；
- 候选字段在进入付费模型前先检查长度；
- 请求排队、重试、最小间隔和健康检查锁共用总等待时间。

服务器定向测试 109 项、完整测试 146 项全部通过；最终静态复审没有剩余高或中优先级问题，
也没有残留测试进程。

两个不阻止提交的部署事项：

- Python 自带网络库无法保证对“持续发送极少数据但始终不断开”的恶意连接在绝对时刻中止，
  生产环境仍要由入口代理限制连接时长和并发数；
- 返回给前端的候选链接还可以对少数控制字符和端口写法做更严格的格式整理，但服务端不会访问这些链接。
