## 一、Urmotiv 侧新增

### 提交前查重链路（插件钩子真正接通）

- `apps/api/src/review-item-store.ts`：审核条目存储（数据库版 + 内存版）。条目挂在审核轮次上，
  带来源（human/anklang/fermata/plugin）与三级可见性（作者/审题人/管理员）。
- `service.submitProblem` 在核心检查通过后调用插件的提交前检查；`block` 直接以 409 阻止提交，
  `continue` 返回的审核条目与新题目修订在**同一个数据库事务**里落库。
- `POST /api/v1/problems/:id/similarity-check`：手动原题检索。草稿阶段只返回结果不落库，
  已进入审核轮次才保存为条目。没有启用任何检查时返回 `status: "unavailable"`。
- `GET /api/v1/problems/:id/review-items`：按身份收窄可见级别返回条目。
- `builtin-plugins.ts` 改成 `createBuiltinPluginDefinitions(runtime)`：Anklang 的钩子在**每次运行时**
  读取插件设置与密钥，管理员改配置无需重启。

### 机器人审题链路

- `apps/api/src/robot-store.ts` + `/api/v1/robot/review-tasks/{claim,renew,complete}`：
  Bearer 令牌认证（只存摘要、撤销/过期即失效）、待审任务领取（逐题权限过滤 + 租约唯一）、
  乐观续租、完成时校验租约与题目修订后走标准审核流程（来源自动记为 `fermata`）。
- 审计只记录实验版本与模型配置名，不含题面或意见正文。
- 反例测试：机器人被误授组长角色后，固定禁止项（删除题目/用户、模拟登录、权限与系统管理等）
  仍然全部拒绝。

### CAS 学号闭环

- 登录时把 CAS 返回的学号写入 `user_identifiers`（`URMOTIV_CAS_STUDENT_ID_ATTRIBUTES` 配置字段名）。
- 学号已绑定其他账号时**保持原绑定不自动改绑**，留给管理员按“歧义需人工确认”处理。
- CAS 稳定身份字段仍是配置驱动：填占位值后真机点一次登录，若取不到会返回
  `subject_attribute_missing` 并**在错误里列出本次 CAS 实际返回的全部字段名**，照着回填即可。
  这一步需要真实统一身份账号，只能由本人在浏览器完成。详见 `docs/deployment.md`。

### 顺带修掉的三个真实缺陷

1. `database-plugin-store.ts` 登记内置插件时 `installed_by_user_id` 写死为 `1`，而种子只创建 `0` 号
   root——**全新部署会因外键失败直接启动崩溃**（旧 e2e 数据库掩盖了它）。
2. 同一文件的用户编号正则 `^[1-9]\d*$` 不接受 `0`，导致 root 无法操作插件。
3. `database-contest-store.test.ts` 用写死的 2026-07-26 时钟，会随真实时间推移变成过期会话而失败
   （定时炸弹），已改为以运行时刻为基准。

## 二、Anklang（原题检索）

**零第三方依赖**：部署服务器没有 pip/venv（ensurepip 不可用），所以全部用 Python 标准库实现——
sqlite3 存题、urllib 调接口、手写余弦相似度。

### 阶段 1：yuantiji.ac 反向代理（生产默认）

把 Urmotiv 的查重请求转成 yuantiji.ac 的公开检索请求再映射回统一契约，按内容摘要缓存，
可选调用 LLM 复核最相似的前几组是否同题。对上游保持克制（串行 + 最小请求间隔）。

**真机联调通过**：查一道数组求和题，返回 8 道候选、最高相似度 0.898，契约字段（apiVersion、
contentHash 回显、recommendation）与 Urmotiv 插件的 zod 校验完全对齐。

### 阶段 2/3：本地检索引擎 + 源插件框架

- 检索后端抽象成 `SearchBackend`，按 `ANKLANG_BACKEND` 切换 `reverse_proxy`（默认）/`local_engine`。
- `store.py`：sqlite3 存题目与 1024 维向量（struct 打包成 blob），按 (source, external_id) 去重。
- `embedding.py`：百炼 `text-embedding-v4`（`{DASHSCOPE_BASE_URL}/embeddings`，base 已含
  `/compatible-mode/v1`）。**任何异常都包装成 `EmbeddingError`**，确保检索能降级成关键词召回，
  而不是让整个查重请求失败。
- `sources/`：源插件框架 + `example_static` 示例源。`python -m anklang.ingest` 跑一轮抓取入库。
- **不含真实爬虫**。vjudge 源仍按规划暂缓（规模、合规、注册机/代理池风险）。

**端到端验证**：示例源 5 道题入库（真实 embedding 全部成功），然后用一句**全新措辞**的题面
（“有 n 个整数，请你把它们全部加起来”）查重，引擎把语义相同但文字完全不同的两道题排在最前
（改写版 0.825、原版 0.797），不相关的交互题降到 0.521——正是原题机应有的行为。

## 三、Fermata（AI 审题）

四条流水线 + 主循环 + 管理端口，136 个测试全绿。

### 流水线设计（回应“不能让 LLM 凭感觉”）

- **CF 难度**：提示词里放真实锚点题（题面摘要 + 官方 rating）做少样本参照，输出整百难度。
- **思维难度**：第一步用带思考的模型只看题面解题（记录 reasoning 叙述）→ 第二步用另一个模型
  对比标准题解，输出结构化信号（是否想出、思路相似度、自我否定次数、关键洞察数）→
  **第三步纯代码公式**映射到 1-5。
- **代码难度**：让模型写精炼竞赛风格代码 → 统计有效行数、嵌套深度、数据结构使用（按权重表）→
  纯代码映射到 1-5。
- **综合评审**：题面题解 + 三项难度 + 已有审核条目（含原题相似度）→ 结构化审核意见；
  “相似度超阈值 **且** 模型确认同题”才强制不通过，不盲目采信分数。

### 实验结果（`experiments/results/`）

数据集用公开的 open-r1/codeforces（CC-BY-4.0，经 hf-mirror + 纯 JS parquet 读取抽样）——
服务器能访问 CF API 但题面网页被 Cloudflare 拦截，所以改用公开数据集。

| 实验 | 结果 |
| --- | --- |
| CF 难度（无锚点基线） | 24 题，MAE≈283，±200 命中 **54.2%** |
| CF 难度（补 7 条真实锚点） | 33 题，MAE≈282，±200 命中 **63.6%**（命中率 +9.4 个百分点，锚点有效） |
| 综合评审判定 | 正常组 3/3 未误判为不通过；注入相似度 0.95 的**人工构造原题条目**后 3/3 触发强制不通过 |
| 思维/代码难度标定 | 小样本下思维难度随 rating 单调不降；**代码难度出现非单调段**，报告如实标注“启用前需扩大标定集并调整权重后重跑” |

评测脚本会自动把锚点题从评估集排除（防 few-shot 泄漏），支持 `EVAL_CONCURRENCY` 并发。
README 的“当前校准状态”表已用真实数字替换“未跑过”。

## 四、历史题目迁移

`hist_problem/` 71 个文件格式各异（45 个 md、23 个 zip、pdf/png/xlsx 附件，还有一个文件多道题、
编号区间），`USTC题目列表.xlsx` 100 条元数据。工具在 `scripts/migrate-hist/`：

1. `parse-metadata.py`（标准库读 xlsx）：输出迁移字段，**主动剔除 QQ 号**、丢弃审核人列，
   难度从名称里的区间取中点到整百。
2. `apps/api/scripts/migrate-hist.ts`：用便宜模型（deepseek-v4-flash）逐题规范化，产出原生题目包 +
   预览 JSON + 汇总报告；一个文件多道题会自动拆成多项。

**端到端验证**：4 个产出包（1 单题 + 3 拆分自多题文件）全部能被原生格式适配器 `inspect`（零问题）
与 `import`（拿到标题/难度/题面）正确解析。样例质量：题名“科大数”、难度 900、题面含 KaTeX 完整、
有题解、迁移备注如实标注“输入输出格式未在原文中明确给出”。

导入账号策略：原生包不含作者身份，学号保留在包的迁移备注里。可以先用一个共享的“历史导入”账号
统一导入，日后按学号逐步转移归属，不必等所有出题人完成统一身份首登。

## 八、安全边界（不变，实现已遵守）
