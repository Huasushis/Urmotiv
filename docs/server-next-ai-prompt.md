# 给服务器新 AI 的接手提示词

你现在接手 USTC 算法竞赛协会的题库与命题协作系统。唯一工作根目录是：

```text
/home/ubuntu/codex-urmotiv
```

这是三个独立仓库组成的项目：

- `Urmotiv/`：题库、投题、审题、组题、权限、导入导出和插件系统；
- `Fermata/`：AI 审题服务；
- `Anklang/`：原题检索服务。

开始后不要立刻改代码。完整阅读根目录的 `README.md`、`AGENTS.md`、`HANDOFF.md`，再按其中顺序阅读三个仓库自己的 `AGENTS.md`、规格和权限文档。然后分别运行 `git status --short --branch` 和 `git log -5 --oneline --decorate`，以服务器当前状态为准。

在不把内容输出到聊天或日志的前提下，阅读 `Urmotiv/private/urmotiv.txt`。这是用户最初的产品想法，最终验收必须逐项对照它。真实题目、题解、测试数据、附件、题目表格、账号、令牌、密钥和模型原始回答不得进入 Git、日志、错误信息或聊天回复。

## 目录边界

- 本项目原先散落在主目录的环境已经全部归并到这个根目录。
- 正式开发只在根目录的 `Urmotiv/`、`Fermata/`、`Anklang/` 中进行。
- `previous-server-work/` 完整保存迁移前的实验环境、实验结果、私有配置、数据库测试状态、浏览器程序、Linux Node.js 和研究资料。它不是垃圾，也不是正式代码来源；默认只读，不能批量删除或覆盖回正式仓库。
- `validation/` 保存不含私密内容的迁移与测试证据。
- `/home/ubuntu` 下的其他文件和项目都不属于本项目。不要凭名称判断归属；`/home/ubuntu/cc.sql` 明确不属于本项目，不得查找、恢复或处理。
- 服务器上还有其他项目。不能整理用户主目录、改动其他项目或按名称批量结束 Node.js、Python、pnpm 等进程。结束进程前必须核对进程号、父进程、完整命令和工作目录。

服务器代理位于 `127.0.0.1:10808`，HTTP 和 SOCKS5 都可用，变量已写入 `.bashrc`。允许安装项目所需软件和配置，但优先把项目专用工具和缓存留在本根目录。复制来的 `node_modules` 可能包含 Windows 平台文件，不能当作 Linux 依赖已安装；根据锁文件在服务器重新核对。

不要用 `source` 或 `.` 加载 `.env`。Fermata 必须使用 `scripts/run-with-env.mjs <环境文件> <命令>`，避免特殊字符让命令失败并显示密钥。

## 第一优先级

1. 静态复核 Urmotiv 尚未提交的审核改动：有读取权限的用户可看允许公开的评价；内部备注不能公开；只能编辑本人评价；修改评价会重新运行审核规则并可能改变题目状态。重点检查跨账号缓存、草稿、关闭轮次、伪造审核人、失败回滚和无权访问。
2. 在服务器运行 API/Web 类型检查、目标单元测试和桌面/手机页面测试。当前最终修改尚未验证，不能沿用较早的“已通过”结论。
3. 单独审阅和测试题目包审计改动，不能与审核功能混成一个提交。
4. 完成历史题目人工分组工具和合成测试，再处理 `hist_problem/`。顶层 71 个混合文件不是 71 道题；一个文件可能含多题，一题也可能分散在多个文件中。对照 `USTC题目列表.xlsx`，每题生成系统原生题目包并走正式导入接口，不要直接写数据库。

## Fermata 准确性与付费请求

Fermata 的连接与长时间输出问题已经修复，但“程序测试通过”不等于“AI 判断准确”。迁移前报告仍在：

- `previous-server-work/urmotiv-codex/fermata-repo/experiments/results/`；
- `previous-server-work/urmotiv-codex/fermata-accuracy-20260731/experiments/results/`；
- `previous-server-work/urmotiv-codex/fermata-timeout-review-20260731/experiments/results/`。

开始新实验前先登记旧报告，保留修改前后对照。不得恢复 120 秒总时限；正常持续输出的付费请求使用流式接收，也就是边生成边读取，并等待服务器真正结束。要区分没有首段输出、输出中途停住、网络错误、正常慢速生成和主动取消。任何 499、取消、缺失或跳过样本都必须让报告判为不完整，不能拿不完整结果调提示词、处理步骤、难度权重或阈值，也不能重复浪费已经发起的付费请求。

准确性实验必须使用足够大、有人工作为答案的标定集。先跑完整旧方案并保留报告，再用唯一标签运行候选方案。继续核实 CF 难度、思维难度、代码难度、标签、质量、修改建议以及通过/需要修改/不通过是否符合 `private/urmotiv.txt` 的原意。

在把历史 USTC 私有题面或题解发送给外部模型前，必须先向用户明确询问：

> 是否明确同意把历史 USTC 私有题目的题面和题解发送给当前配置的外部模型服务，用于准确性标定？

没有得到明确同意时，只能使用公开题目或人工脱敏材料。

## 安全与完成标准

- 权限检查必须在服务端完成；隐藏按钮不是权限控制。
- 无权访问私有题目、文件、任务或导出包时，响应必须与资源不存在一致，不能泄露标题、文件名、总数或存储位置。
- 明确拒绝永远优先于角色和插件允许。机器人固定禁止删除题目或用户、模拟登录、管理权限或系统、读取密钥。
- 导入压缩包要防止路径跳出、符号链接、异常压缩、重名覆盖和超限文件；导出在创建和下载时都重新检查权限。
- 涉及权限、认证、附件、导入导出或插件时，必须补无权访问和失败路径测试。
- 所有类型检查、测试、构建、数据库迁移、服务运行和浏览器联调都在这台服务器完成。页面改动使用桌面和手机视口检查。
- 界面和文档使用简体中文，不要为了显得专业而造新词；技术名词第一次出现时用日常语言解释它是什么、为什么需要。
- 不得把未运行的测试写成通过，也不得把旧实验目录的存在误写成当前功能已经验收。

读完交接材料、核对三个仓库和旧实验资料后，可以自行创建新的 goal，并从第一优先级继续工作。
