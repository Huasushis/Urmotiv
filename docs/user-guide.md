# 用户指南

本指南面向投稿人、审题人和命题组成员。页面会根据服务端返回的能力隐藏或禁用按钮，但真正的权限检查始终发生在服务端。看不到某个题目或文件时，系统可能故意按“不存在”处理，避免泄露私有资料。

## 页面和题目状态

登录后左侧导航进入：

- **题目**：`/problems`，按关键词、状态和知识点筛选；`/problems/new` 新建草稿。
- **组题方案**：`/contests`，创建和维护比赛题目集合。
- **导入 / 导出**：`/transfer`，处理 Hydro 或 FPS XML 题目包。
- **个人资料**：`/profile`，修改自己的昵称、邮箱和头像。

题目有四种状态：

1. **草稿**：继续编写、补充文件或删除自己的草稿。
2. **待审**：投稿人提交的当前修订等待审核；基础题面和基础题解冻结。
3. **通过**：审核规则达到条件，或有最终状态权限的人员确认通过。
4. **不通过**：审核规则判定不通过，或最终状态权限的人员确认不通过。

每次保存都会带上“期望修订号”。如果另一个人先保存，接口会返回冲突而不是覆盖对方内容；刷新题目后重新编辑并保存。

## 题目仓库（repository）

“题目仓库”是站内题目集合，不是 Git 代码仓库。`/problems` 默认只列出你有权知道的题目；可以按标题关键词、状态和知识点筛选，点击题目进入工作区。列表不会透露无权题目的标题、拥有者、文件名或总数。投稿人通常从自己的草稿开始，审题人从可见的待审题目开始；批量导入/导出另受题目包权限控制。

## 投稿：从草稿到审核

1. 打开“新建题目”，填写题目名称、类型（传统题、交互题或提交答案题）、至少一个知识点，以及可选的思维难度和代码难度，保存草稿。
2. 在工作区的“题面”标签补齐基础题面、背景、正式题面、输入格式、输出格式、数据范围与限制。
3. 在“题解”标签填写基础题解、正式题解和提示；基础题解供审题流程使用，提交后会冻结。
4. 在“样例”标签添加输入、输出和解释；样例最多 50 个。
5. 在“评测”标签填写时间（毫秒）、内存（MiB）、总分、子任务/数据点，以及与题型匹配的程序文件。
6. 检查“程序与附件”中的公开附件、内部附件和标准程序，然后点击“提交审核”。

提交前，已启用的提交前检查会按管理员配置的顺序运行。任何检查返回 `block` 或在“阻止提交”策略下超时/失败，题目都不会进入待审；`continue` 结果会继续累积审核条目。提交完成后，题目的修订号和审核轮次都会改变。

题目没有“撤回后继续改成同一待审版本”的隐式行为。需要撤回时使用工作区的“撤回”操作并填写原因，再按页面提示修改和重新提交。

作者可以在自己的草稿工作区顶部点击“删除”，二次确认后软删除。已提交或已通过的题目不能由作者直接删除；管理员仍须具备专门的全局删除权限。删除后普通读取统一按“不存在”处理，服务端会记录不含题面内容的审计事件。

## 审题：意见、建议和终审

有 `problem.review` 权限且能查看该题目的审题人，可以在“审核”标签填写：

- **结论**：通过、要求修改或不通过。
- **难度字段**：Codeforces 难度为 800–3500、步长 100；思维难度和代码难度为 1–5。
- **改进点**：必填，说明题面、数据或解法需要改进之处。
- **公开意见**：作者和有权审阅者可见。
- **内部备注**：仅内部权限和管理员可见，不要在这里放密码、令牌或不应进入题库的原始资料。

意见必须针对当前审核轮次；轮次变化后提交旧意见会失败。默认的内置审核规则要求 2 份有效通过意见，且任意 1 份不通过意见会阻止通过；管理员可以调整规则。默认不把机器人意见计入人数。拥有 `problem.status.change` 的人员会在待审核题目的“审核记录”中看到“人工终审”，可以填写理由后直接确认通过或不通过，也可以强制撤回。

同时拥有全局 `problem.view.all` 和 `problem.status.change` 的真人账号，可以进入“管理 → 题目管理”。页面支持按状态、来源和导入批次筛选并跨页选择题目，批量执行提交审核、确认通过、确认不通过或撤回为草稿。除提交审核外都必须填写理由；服务端会逐题检查当前修订和审核轮次，冲突项失败而不会覆盖其他人的新修改。

审核规则会过滤旧轮次、无权审阅者和不匹配内容摘要的意见。审核条目（例如服务返回的结构化结果）有作者、审题人、管理员三级可见性，并且只能引用同一题目修订的内容摘要。

## Markdown 题面

Markdown（用普通字符标记标题、列表、代码和链接的文本写法）编辑框提供“编辑 / 预览”切换，支持 GFM（GitHub 风格 Markdown）和 KaTeX 数学公式。首次使用时可以从最小结构开始：

```markdown
# 题目说明

给定一个整数数组，求它的和。

## 输入格式

一行整数。

## 输出格式

输出一个整数。

行内公式：$a+b$。
```

上传题面图片后，编辑器会插入受权限检查的站内文件地址；不要手写对象存储地址。预览只显示属于当前题目的受控文件，外部图片不会渲染，以免浏览器向第三方泄露访问信息。粘贴图片或选择图片时仅接受 PNG、JPEG、GIF、WebP。

基础题面和基础题解是冻结字段：待审后普通编辑不能修改；有 `problem.frozen.edit` 权限的人员必须使用专用修改操作并填写原因。正式题面、样例、提示和非冻结元数据仍受当前状态与编辑权限限制。

## 文件、评测程序和附件

在“程序与附件”标签上传文件。系统会把文件放在安全的相对逻辑路径下，不接受绝对路径、反斜杠或 `..` 路径；每次上传都会产生新修订号。

| 页面类别 | 用途 | 谁能下载/修改 |
| --- | --- | --- |
| 公开附件 | 随公开题面或题目包导出 | 能查看题面的用户可下载；写入仍需要题目编辑权 |
| 内部附件 | 命题资料，不随公开题面导出 | 需要 `problem.testdata.read`；写入需要 `problem.testdata.write` |
| 测试数据 | 评测输入/输出 | 需要测试数据读取/写入权限 |
| 标准程序 | 核对答案，不出现在公开题面 | 需要测试数据读取/写入权限 |
| 特殊判断程序 | 传统题答案不唯一时使用 | 由题型匹配的评测程序上传并绑定 |
| 交互程序 | 交互题的交互端 | 仅交互题可绑定 |
| 答案判断程序 | 提交答案题的判分端 | 仅提交答案题可绑定 |

传统题没有绑定特殊判断程序时使用标准比较；交互题绑定交互程序；提交答案题绑定答案判断程序。上传或更换评测程序时不要同时保存其他正文修改，页面会提示等待上传完成。

## 组题与比赛装配

打开“组题方案”并新建方案：

1. 填写标题、描述、可选的开始/结束时间。
2. 添加成员并选择 `participant`（参赛者）或 `manager`（管理者）。创建者始终是管理者；机器人账号不能作为参赛者。
3. 添加至少一道题，填写正整数分值和可选的预估难度。题目必须已经审核通过。
4. 保存为 `draft`（草稿）并检查题目、成员和泄题风险信息。
5. 确认后把状态改为 `locked`（锁定）。锁定会固定每道题当前修订、成员和比赛信息；锁定后只能归档，不能替换题目或成员。

`contest.risk.read` 权限只显示访问记录与参赛成员的风险条目；没有这项权限时，风险计数和详情不会泄露给你。组题页面不是审核状态的替代物，题目是否通过仍由题目状态和审题权限决定。

## 导入题目包

导入支持已注册的格式适配器，当前内置格式编号为 `hydro`（Hydro 题目包）和 `fps`（FPS XML 题目包）：

1. 打开“导入 / 导出”，选择题目包文件；上传请求使用 `application/octet-stream`。Hydro ZIP 可以是根目录中的一道题，也可以在根目录放多个直属题目目录；FPS XML 可以包含多个 `item`。
2. 选择格式并先点击“预览”。预览会显示题目数、文件清单和错误/警告，不会写入题库。
3. 确认预览没有阻止性错误后创建导入任务。页面显示队列、读取、转换、写入、完成或失败阶段。
4. 刷新任务状态；失败项有固定错误编号和面向用户的消息，不会在任务记录中返回题面或文件内容。

导入器拒绝路径穿越、符号链接、重复覆盖、嵌套压缩炸弹、超出条目/字节上限的归档。导入需要 `problem.import`。格式的详细字段和安全约束见[题目包参考](problem-package.md)。

## 导出题目包

导出需要 `problem.export.own`（自己的题目）或 `problem.export.all`（任意可见题目），并先通过预览：

1. 选择目标格式和一个或多个不重复的题目编号。
2. 指定是否包含公开附件、内部附件、测试数据、评测程序和标准程序。
3. 查看预览中每题的 `ready`、`blocked` 或 `not_found` 状态，以及可能的损失提示。
4. 只有全部必要项可导出时创建任务，并使用一次性的幂等键（同一请求重复提交不会创建第二个任务）。
5. 任务成功后下载；下载接口会再次检查当前权限，过期或已撤销权限不会因为旧任务而绕过控制。

没有权限的题目和不存在的题目都显示为 `not_found`，不会显示标题、文件名、对象存储位置或筛选总数。

## 个人资料

在 `/profile` 修改自己的昵称；邮箱字段用于邮箱登录和通知身份，服务端会做规范化。头像通过受控上传保存，当前仅接受 JPEG、PNG、WebP，大小不超过 512 KiB。删除头像后页面显示默认头像。个人资料页不能修改角色、权限或其他用户信息；这些操作由管理员完成。

## 安全边界和外部服务

- Anklang 只负责原题相似性检索与受控索引同步：查重和索引必须接收题目名称与基础题面。管理员必须配置本地/私有 `baseUrl`，在“允许将题面发送给 Anklang”中确认 Anklang 与嵌入提供方属于批准的处理范围，并把非空令牌放入 `serviceToken` 插件密钥。停用、未授权、缺密钥和无效设置不会发出题面请求。
- 手动“相似题”和提交前检查只返回按当前用户权限过滤后的候选参考与完成状态；当前题目自身候选、未知、隐藏和明确拒绝不会显示，也不会计数或泄露存在性。授权 Urmotiv 候选显示当前标题，远端 URL、`metadata`（附加信息）和 recommendation/judgment 字段不会进入审核条目。
- Anklang 不决定题目状态、审核结论、用户权限或流程，也不会因为相似候选阻止提交；`failureBehavior` 仅控制无法获取检查时的阻止/继续。Fermata 只能读取 Urmotiv 保存的检查属性，不能把外部建议当成人工终审。
