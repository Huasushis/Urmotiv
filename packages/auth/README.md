# 账号认证基础

这个工作区提供邮箱密码、会话令牌、机器人令牌和 CAS 统一身份认证所需的安全操作。它不直接读写数据库，API 通过接口把
令牌摘要、一次性登录状态和账号绑定保存到 PostgreSQL 或 PGlite。

## 邮箱与密码

- 邮箱只做去除首尾空白和小写化，不擅自删除 `+tag`、句点等服务商可能赋予含义的字符。
- 新密码至少 12 个字符，使用 Argon2id 保存；数据库只保存编码后的密码摘要。
- 登录失败对外使用同一条提示，调用方还应对邮箱和来源地址限速，避免账号枚举和暴力尝试。

## 会话与机器人令牌

创建函数只在生成时返回完整令牌。数据库保存 SHA-256 摘要和显示用的短前缀，完整机器人令牌只显示一次。
会话还要记录账号的认证修订编号；修改密码、邮箱或权限后提高该编号，就能让旧会话失效。

## USTC CAS

实现遵循 Apereo CAS 的 service ticket 校验流程。登录地址、`serviceValidate` 地址、回调地址和稳定身份字段必须显式配置。
`cas:user` 只有在管理员确认它稳定后才能配置为身份字段，程序不会自动把学号当成永久身份。

开始登录时会生成带签名的一次性状态，把它放进 CAS 的 `service` 回调地址。状态最多有效十分钟，并在第一次回调时消费；
这同时防止伪造回调、重复使用和跳转到站外网址。票据校验必须使用开始登录时完全相同的 `service` 地址。

如果配置的稳定身份字段没有返回，错误只列出可用的字段名，不输出字段值。此时需要在真实 USTC 登录联调中确认字段，
不能静默退回学号或昵称。CAS 返回的邮箱可以为空；首次登录账号因此可以暂时没有邮箱和密码。

协议来源：Apereo CAS 官方仓库的 `CAS-Protocol-Specification.md`。
