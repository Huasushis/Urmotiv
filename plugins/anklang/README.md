# Anklang 接入插件

这个插件在用户提交题目前调用独立运行的 Anklang 服务，显示可能相似的公开题目。它只负责连接和严格校验结果，
不把 Anklang 的公开题库复制到 Urmotiv，也不会让远端建议取得审核通过权限。

## 发送的信息

插件发送题目名称、类型、知识点、基础题面和题目内容摘要。它不发送作者、邮箱、学号、基础题解、完整题解、
测试数据、附件、审核意见或 Urmotiv 权限。服务令牌由 Urmotiv 的密钥存储提供，不写入普通插件设置。

新配置默认调用 `POST /api/v2/checks/similarity`，请求正文带 `apiVersion: "2"`。只有迁移或短期回滚仍未升级的
Anklang 时，管理员才应明确把“Anklang 接口版本”设为 `1`；路径、请求正文和响应版本必须一致。响应还必须原样
返回本次内容摘要，并通过严格字段校验，多字段、少字段、非 UTC 时间或超过 2 MB 都按失败处理。

默认最多等待 120 秒。Anklang 查询时依赖的其他服务暂时失败后可能再次尝试，也可以逐个调用模型复核候选；
它自己的部署设置会把这些等待按配置限制在 100 秒内，插件再预留 20 秒用于网络传输和结果校验。只有确认服务
关闭了这些较慢步骤时，管理员才应把等待时间调低。已有安装如果仍保存旧的 30 秒设置，需要由管理员改为
120000 毫秒；系统不会擅自覆盖管理员已经保存的值。

## 完成状态与缓存

v2 会明确区分三种结果：

- `complete`：检索及已配置的复核都完成；只有这一分支的空候选才表示完整检查后没有发现候选。
- `partial`：只完成一部分。候选可以供人工核对，但不能只凭相似度阻止提交；只有本次响应中带
  `sameProblemSuggestion=true` 的可信同题复核才能支撑拦截。
- `unavailable`：无法形成可信候选，必须为空候选且不得建议拦截。

`partial` 和 `unavailable` 固定不可复用。只有 `complete` 同时声明 `reuse.policy=allowed`，内容摘要一致，
`checkedAt` 与 `expiresAt` 都是 UTC 时间，绝对到期时间尚未过去，且两者相差不超过七天时，插件才写入宿主缓存；
读取缓存不会延长到期时间；实际保留时间还会受本地 `cacheMinutes` 上限约束，取两者中较早的时间。
`reuse.policy=no-store` 不进入缓存。明确选择 v1 时只使用 `cacheMinutes`，不同接口版本和服务地址不会共用缓存项。

## 提交行为

- `failureBehavior=block`：服务超时、不可用、返回畸形内容或 v2 没有完整完成时不提交题目，适合强制查重。
- `failureBehavior=continue`：上述失败时继续提交；有效的部分结果会明确标记为“只完成一部分”，不能显示成查重成功。
- `blockWhenRecommended=true`：完整结果明确建议拦截时阻止提交；部分结果还必须有本次可信的同题复核支撑。

阻止响应只含固定错误、候选数量、最高相似度和内容摘要，不会带出题面、候选详情、认证令牌或上游响应正文。
远端建议只是一次提交前检查。核心权限、必填字段、冻结规则和最终审核规则仍由 Urmotiv 判断。
